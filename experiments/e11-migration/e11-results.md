# E11 results: migrating Word on SharePoint and Confluence into AI-XF

**2026-10-03.** Exploratory: no plan with pass criteria preceded it. The question
is what an organisation keeps, loses or leaks when it moves a document library
or a wiki into an LLM knowledge base, and how much of that is the format's job.
Re-run with `run.sh` (needs `uv`); numbers below are from `results.json`.

## Corpus and method

Everything is synthetic, about a fictional company's payments platform
("Northwind Pay"), generated by `make_corpus.py`:

- **Word on SharePoint:** 5 `.docx` files (a design, a runbook, a policy, a data
  dictionary, an incident review) with headings, numbered lists, tables,
  hyperlinks to each other as SharePoint URLs, an embedded image, 4 comments,
  2 tracked insertions and 2 tracked deletions, and core properties. Each has a
  sidecar imitating SharePoint list metadata: document id, content type,
  managed metadata terms, library path, three-entry version history, approval
  status (3 approved, 1 pending, 1 draft).
- **Confluence:** 5 pages in storage format (XHTML with `ac:`/`ri:` elements):
  info, warning and note panels, code, expand, Jira, table-of-contents and page
  properties macros, user mentions, page links, attachments. Each has a sidecar
  imitating the REST API: page id, space, version history with authors, labels,
  ancestors, content status (2 verified, 1 rough draft), restrictions. One page,
  "Refund Policy", is read-restricted to a group.

`ground-truth.json` records 211 probes: one per element a migration could keep
or lose, each with a probe string. Two conversions:

- **naive:** [MarkItDown](https://github.com/microsoft/markitdown) to markdown,
  frontmatter `type` and `title` only. A lift-and-shift export.
- **mapped:** `convert.py`. The same body text, plus all source metadata mapped
  onto AI-XF/OKF fields (below).

`measure.py` classifies every probe in every bundle as **kept** (present with its
meaning), **degraded** (text survived, structure or meaning did not),
**withheld** (deliberately not exported, and the gap is visible), **leaked**
(restricted content reached the bundle) or **lost**.

## Results

| Bundle | Kept | Degraded | Lost | Leaked | Withheld | Validator (level 3) |
|---|---|---|---|---|---|---|
| Word, naive | 35 / 117 | 16 | 66 | 0 | n/a | level **0**; 13 errors |
| Word, mapped | **117 / 117** | 0 | 0 | 0 | n/a | level **3**; 0 errors, 0 warnings |
| Confluence, naive | 22 / 94 | 12 | 57 | **3** | n/a | level **0**; 13 errors |
| Confluence, mapped | 78 / 94 | 0 | 0 | 0 | 16 (one page) | level **3**; 0 errors, 2 warnings |

Both parsers give identical validator output on every bundle; a re-run of the
converter is byte-identical (the migration time is fixed, never the clock).

### What the naive conversion did

**Word.** All 15 version-history entries and 47 of 60 metadata values were lost
(author, modifier, dates, document id, approval, content type, keywords). All 4
comments were dropped. Both tracked insertions appeared in the text as if
accepted, and both tracked deletions vanished, with nothing to say that either
change was still pending. The document title lost its heading (Word's Title
style is not a heading to MarkItDown). The image became a truncated
`data:image/png;base64...` placeholder. All 6 links between documents stayed as
SharePoint URLs: words survive, the graph does not.

**Confluence.** Both user mentions became empty ("Owner:"). Both attachments
disappeared. Code macros merged their language parameter into the code
("sqlSELECT status…"), Jira macros became "NWP-1234Example Jira", panels became
ordinary paragraphs, and all 6 page links became plain words. Version history
(10 entries) and 43 of 53 metadata values were lost. **The restricted page was
exported in full**: title, heading and policy text. A lift-and-shift export
does not know about permissions, and an LLM knowledge base built from it
answers anyone from a page only one group could read.

Neither naive bundle gets past level 0: no `id`, no manifest, no trust field.

### What the mapping does

| Source | AI-XF / OKF |
|---|---|
| SharePoint document id / Confluence page id | `id` (`doc-nwp-1001`, `page-163842`); title and its slug as `aliases` |
| Site / space | manifest `namespace` (`sharepoint-payments-platform`, `confluence-nwp`) |
| Content type / label (`runbook`, `policy`, …) | `type` (Design, Runbook, Policy, DataAsset; Concept by default) |
| Last modifier and time | `generated: {by: human:<name>, at}` |
| Approval "Approved" / content status "verified" | `verified: [{by: human:<approver>, at}]`; anything else gets no `verified` |
| Approval pending or draft / "rough draft" | `status: draft` |
| Original URL and last modified | `sources[0]: {resource, last_modified}` |
| Modified + 365 days | `stale_after` (datetime, SPEC §5.6) |
| Managed metadata, keywords, labels | `tags` |
| Parent page | `part-of` link |
| Links to other documents and pages | resolved to `references` links and relative body links |
| Authors, approvers, mentioned users | `Person` concepts; `authored-by` and `references` links |
| Embedded image | `media` with `sha256` hash, file in `assets/` |
| Confluence attachment (binary not exported) | `media` with the original URI, no hash (the 2 warnings) |
| Version history | `log.md`: `Creation`, then `Update` per version, with author |
| Open Word comment | body section "Open review comments", and a `Gap` entry in `log.md` |
| Tracked changes | body section "Pending tracked changes", stating that the text shows them as accepted |
| Panels, code, expand, Jira, page properties | blockquote with label; fenced code; bold title plus body; link to the issue; table, plus `confluence.properties` |
| Table of contents macro | dropped (regenerable from headings) |
| Restricted page | **not exported at all**; the 2 links to it become "a page withheld from this export" |
| Everything else the source knew | custom `sharepoint:` / `confluence:` maps (document id, content type, library path, approval, version, permissions, open-comment and pending-change counts) |

Why the id comes from the system's id, not the title: titles change (E8 showed
that a filename-derived id turns every rename into a delete plus an add), while
a Confluence page id survives renames and moves, and a SharePoint document id
survives moves between libraries. The title stays findable as an alias.

The mapped bundles also exercise v0.4.3's `--stats`. The data dictionary was
approved in June 2025 and edited in August 2025, and is reported both as
changed since verified and as past `stale_after`. The Confluence orders page
is past `stale_after` too. That is migration surfacing review debt the source
system held but did not show.

## Losses the probes do not measure

The mapped score is partly circular: the same person wrote the probes and the
converter. These losses are real and unprobed:

- **Comment anchors and threads.** Which words a comment was attached to,
  replies, and resolved state are gone; only author and text survive.
- **Where a tracked change sat.** Pending changes are listed, not located.
- **Code language.** MarkItDown drops the `language` parameter, so fences
  have no language tag.
- **Earlier versions' content.** `log.md` records that each version happened,
  by whom and why, but not what it said.
- **Sibling order and the space home page** beyond `part-of`.
- **Attachment binaries** (Confluence), which need a separate download.
- **Permissions themselves.** The mapping decides what to withhold. It does
  not record who could read what, and should not.
- **Live macros.** A Jira macro shows an issue's current status; a link does
  not. Any macro that is a query (children, page properties reports) is
  frozen or lost.
- **Person identity.** People are keyed on display names; two people with one
  name would merge. The source's account id should be the key.

## What AI-XF cannot express, and where it belongs

| Need | Belongs in | Note |
|---|---|---|
| A link to something withheld, without naming it | **Format** | The mapping had to write prose ("a page withheld from this export"). §7.5 has `withheld` for sources only. A link-level marker is the same idea, and the archive discussion after E8 needs it too. |
| Distinguishing "pending approval" from "draft" | Format (or custom key) | Both map to `status: draft`; the distinction rides in `sharepoint.approval`. |
| A stable person identity across systems | Policy and tool | `human:<id>` already allows any id; the tool should use the account id, not the display name. |
| Comment threads and annotations | Policy | Most comments are transient. An unresolved one is an open question (`Gap`); a resolved one is history. The format should not grow an annotation model. |
| Pending revisions | Tool | A pending change is a proposal: migrate the accepted state and open the rest as a branch, not a field. |
| Full version content | Tool | Replay versions as git commits if history matters; `log.md` stays the summary. |
| Permissions | Tool and policy | Decide at export; never record ACLs in the bundle. |
| Attachments | Tool | `media` with a hash already fits once binaries are fetched. |
| Live macros | Tool | Freeze with a timestamp, or link. |

## Maturity journey: from a wiki or library to an LLM knowledge base

1. **Lift and shift.** Export and convert. Cheap, and it reads well at a
   glance. Measured here: around a fifth to a third of what the source knew
   survives with its meaning, no trust or history, links that point back at
   the old system, and restricted content leaked. Useful only as a private
   search index, and dangerous as anything an agent answers from.
2. **Mapped migration with provenance.** A converter per source system that
   maps ids, trust, history, links and media, withholds restricted content,
   and reaches level 3. Measured here: every probe kept or deliberately
   withheld, and the review debt (stale, changed-since-approved) made visible
   on day one. The source system is still where people write.
3. **Curated and compounding.** Writing moves to the knowledge base. Curation
   rules (CURATOR.md: search before writing, contradictions as tickets,
   retire not delete) replace the old approval workflow; `verified` comes
   from reviews in the new system. The measure becomes the update-to-creation
   ratio, not the page count. Comments become `Gap` entries and get closed.
4. **Federated department bundles.** Each team owns a bundle with its own
   namespace; cross-team links are qualified; a federation manifest pins what
   each consumer read. Migration from stage 2 is cheap because ids, namespaces
   and links were stable from the start.
5. **Database-backed, if writes outgrow git.** When many people write at once,
   a database becomes the write side, and bundles become an export and an
   interchange format (as Longview already does). The stable ids, the
   deterministic export and `log.md` as an event record are what make that
   step reversible.

The step that matters most is 1 to 2. Everything after it depends on the ids,
provenance and withholding decided at migration time, and none of it can be
recovered later from a naive export.

## Limits

Ten synthetic documents, written to contain the features being measured. One
conversion library (MarkItDown) for the naive path and for body text in the
mapped one. No real Confluence export (real storage format carries more macro
types and broken markup) and no real SharePoint API. The probes were written by
the converter's author. Treat the naive numbers as indicative and the mapped
numbers as a ceiling.
